# Folio 0.3 — Navigation, writing, viewing and app comfort

Date: 2026-10-09
Status: Draft — awaiting review
Builds on: `2026-10-07-folio-desktop-design.md` (Folio desktop 0.2.0, merged)

## Goal

Make Folio comfortable for daily reading and writing: an outline of
headings, find, quick open and folder search; formatting shortcuts, pasted
images, word count and crash recovery; zoom, theme, diagrams, maths and
export; session restore, sidebar file operations and auto-update.

## Decisions already made

| Topic | Decision |
|---|---|
| Ctrl+B | **Bold** in the editor. Sidebar toggle moves to **Ctrl+Shift+B**. |
| Autosave | Crash-recovery drafts **always on** (never touch the user's file). Autosave to the real file is an opt-in toggle, **off** by default. |
| Auto-update | Included. Updates come from the repo's GitHub Releases; the user does a one-time signing-key setup. |
| Sidebar delete | Moves to the **Recycle Bin**, after a confirm prompt. |
| Mermaid / maths | **Desktop only.** The single-file web viewer does not change size or behaviour. |
| Version | `0.3.0` |
| Delivery | Four phases, each ending with a working app and a green CI installer. |

## Success criteria

1. Every feature below works in the installed Windows app and in the
   browser against the fake backend.
2. Nothing the user typed is lost by a crash, a power cut or a forced quit:
   on the next launch the unsaved text is offered back.
3. Folio never writes to a user's file unless the user saves, or turned
   autosave on.
4. Works offline. Markdown content still can't run scripts — including
   through diagrams and maths.
5. `dist/folio.html` still builds, behaves as before, and its tests stay
   green.
6. A tagged release produces a signed update that a 0.3.0 install can find,
   download and install.

## Architecture changes

Same layering as 0.2: pure logic in small modules (JS in `src/desktop/`,
Rust in `src-tauri/folio-core`), a thin Tauri command layer, and
`backend.js` as the only module that touches Tauri (with the fake mirroring
every new call).

`src/desktop/main.js` is ~1,000 lines. Each feature lands as its own module
and `main.js` only wires them; touched code moves out of `main.js` where a
feature takes it over (no unrelated refactors).

New JS modules (pure unless noted): `outline.js`, `find.js` (DOM), `fuzzy.js`,
`quickopen.js` (DOM), `search.js` (DOM view), `format.js`, `wordcount.js`,
`drafts.js`, `session.js`, `settings.js`, `menu.js` (DOM), `diagrams.js`
(DOM, lazy), `exporter.js`, `fileops.js`, `updater.js`.

New Rust modules in `folio-core`: `search.rs`, `fileops.rs`, `drafts.rs`,
`settings.rs`, `image.rs`.

### New commands (`backend.js` mirrors 1:1)

| Command | Args | Returns |
|---|---|---|
| `search_folder` | `folder, query, matchCase, requestId` | `{ requestId, files: [{ path, matches: [{ line, text, start, end }] }], truncated }` — `line` is 1-based; `text` is the line trimmed to 200 chars around the match; `start`/`end` are char offsets into `text`. A newer `requestId` cancels any running search. |
| `create_file` | `path` | `()` — error `"already exists"` if present. Creates an empty file. |
| `create_dir` | `path` | `()` — error `"already exists"` if present. |
| `rename_path` | `from, to` | `()` — error `"already exists"` if `to` exists (case-only renames allowed). |
| `trash_path` | `path` | `()` — moves a file or folder to the Recycle Bin. |
| `write_image` | `path, base64` | `()` — only image extensions (same list as the asset scope); creates the parent folder; error `"already exists"` if present. |
| `settings_get` | — | `Settings` (missing/corrupt file → defaults) |
| `settings_set` | `settings` | `()` |
| `drafts_list` | — | `Draft[]` |
| `draft_save` | `draft` | `()` |
| `draft_delete` | `id` | `()` |

Existing `read_file`/`write_file` are reused for exporting HTML.
*Show in Explorer* uses the opener plugin's reveal call. Updates use
`tauri-plugin-updater` and `tauri-plugin-process` (relaunch).

Errors stay readable strings, never panics.

### Stored data (app config dir)

- `settings.json`:
  `{ zoom: 100, theme: "system"|"light"|"dark", autosave: false,
     sidebar: { visible: true, tab: "files"|"outline"|"search" },
     session: { tabs: [{ path, mode }], active: path|null, folder: path|null } }`
- `drafts/<id>.json`: `{ id, path|null, title, text, eol, bom, savedAt }`
  where `id` is the tab's draft id (stable for the tab's lifetime).

## Phase 1 — Getting around

### Sidebar tabs

- The left sidebar has three tabs: **Files | Outline | Search**.
- **Ctrl+Shift+B** shows/hides the sidebar (was Ctrl+B).
  **Ctrl+Shift+L** shows it on Outline; **Ctrl+Shift+F** shows it on Search
  and focuses the query box.
- The sidebar can be shown with no folder open. Files then shows an
  **Open folder** button; Search shows `Open a folder to search it.`
- Width 260px and auto-hide below 700px stay as in 0.2. The visible state
  and the selected tab are remembered (Phase 4 persists them; until then
  they last for the session).

### Outline

- Lists the Markdown headings (`#` … `######` and setext) of the active
  tab in document order, indented by level. Headings written as raw HTML
  are not listed.
- A heading with sub-headings has a disclosure triangle; all start
  expanded. Collapse state is per tab and survives switching tabs.
- Clicking a heading:
  - **Read / Split:** scrolls the rendered document so the heading is at
    the top (Split also moves the editor cursor to it).
  - **Edit:** moves the cursor to the start of that heading's line and
    scrolls it into view.
- The current section — the last heading at or above the top of the
  visible document (Read/Split), or the heading above the cursor (Edit) —
  is highlighted and scrolled into view in the outline.
- Updates while typing on the same delay as the Split preview.
- An empty document or one without headings shows `No headings`.

### Find in Read mode

- **Ctrl+F** in Read (and in the Split preview when it has focus) opens a
  find bar above the document: query box, `3 of 12` count, ↑ / ↓ buttons,
  a **Aa** match-case toggle and ✕. In Edit/Split-editor Ctrl+F still opens
  CodeMirror's search.
- Matches are highlighted without changing the document's DOM (CSS Custom
  Highlight API); the current match has a stronger colour and is scrolled
  into view.
- Enter / F3 = next, Shift+Enter / Shift+F3 = previous, Esc closes and
  clears highlights. Matching is plain text, case-insensitive by default,
  across the rendered text (including code blocks).
- No matches shows `No results`. Re-rendering (reload, typing in Split)
  re-runs the current query.

### Quick open

- **Ctrl+P** opens a centred palette with a text box and up to 50 results.
- Source: all files in the open folder's tree; with no folder, the recent
  files.
- Fuzzy match on the file name first, then on the path relative to the
  folder; matched characters are bold. Results show name + dimmed relative
  folder.
- ↑/↓ select, Enter opens (focuses the tab if already open), Esc closes.
  Empty query lists recently opened files first.
- Print moves to the ⋯ menu because Ctrl+P is quick open.

### Search across the folder

- The Search tab has a query box, an **Aa** match-case toggle and results
  grouped by file (file name, match count, then `line: snippet` rows with
  the match bold).
- Searches start 250 ms after typing stops; a newer query cancels the
  running one. Same skip rules as the tree (`.`-names, `node_modules`,
  only `.md`/`.markdown`). Stops at **1000 matches** and then shows
  `Showing the first 1000 matches`.
- Clicking a result opens/activates the file, then:
  - **Edit / Split:** selects the match on that line.
  - **Read:** opens the find bar with the query and selects the Nth
    rendered match, where N = the number of matches in the source before
    that line (falls back to the first match).
- `folder-changed` does not re-run a search automatically; a ↻ button does.

### `#section` links

- After a link to `other.md#section` opens (or activates) the file, Read
  mode scrolls to the heading whose id matches `section` (URL-decoded,
  `user-content-` prefix handled as for in-page anchors). Edit/Split move
  the cursor to that heading. Unknown anchors leave the scroll alone.

## Phase 2 — Writing

### Formatting shortcuts (editor only)

| Keys | Effect |
|---|---|
| Ctrl+B | `**bold**` |
| Ctrl+I | `*italic*` |
| Ctrl+K | `[text](url)` with `url` selected |

- With a selection: wrap it. Without one: insert the markers and put the
  cursor between them (Ctrl+K inserts `[](url)` with the cursor inside `[]`).
- Pressing Ctrl+B / Ctrl+I again on a selection that is already wrapped
  (markers just inside or just outside the selection) removes the markers.
- Multiple selections are each handled. One undo step per shortcut.

### Paste an image

- Pasting image data (e.g. a screenshot) into the editor of a saved file
  writes it to `<document folder>/images/<document name>-YYYYMMDD-HHMMSS.png`
  (adding `-2`, `-3`… if taken) and inserts `![](images/<file>.png)` at the
  cursor. The path in the link uses `/` and is URL-encoded where needed
  (spaces → `%20`).
- Untitled tab: nothing is written; banner `Save the file first to paste images.`
- Write failure: banner `Couldn't save the image: <reason>`.
- Pasting text is unchanged.

### Word count

- Toolbar shows `1,234 words · 6 min read` for the active tab (230 words
  per minute, rounded up, minimum `1 min read`; hidden for an empty tab).
- Counts words in the Markdown source excluding fenced/indented code and
  front matter; link URLs and image targets are not counted.
- Updates on the preview delay.

### Crash recovery (always on)

- While a tab is dirty, its draft is saved 2 s after typing stops (and at
  most every 10 s while typing continues) to `drafts/<id>.json`.
- The draft is deleted when the tab becomes clean (saved, reloaded, or
  closed with **Don't save**).
- On launch, drafts that remain are restored as tabs, before session
  restore and double-clicked files: a draft with a path opens that file's
  tab with the draft text (dirty); an untitled draft opens as an untitled
  tab. Each shows the banner `Recovered unsaved changes.` with **Keep** /
  **Discard** (Discard reverts to the file on disk, or closes an untitled
  tab, and deletes the draft).
- If a draft's file changed on disk since `savedAt`, the banner is
  `Recovered unsaved changes. <name> also changed on disk.` with the same
  buttons.

### Autosave (opt-in)

- Toggle **Autosave** in the ⋯ menu (off by default, remembered).
- When on, a dirty tab with a path is saved 1 s after typing stops, using
  the normal save path (EOL/BOM kept, errors show the save banner and stop
  autosave for that tab until the next manual save). Untitled tabs are not
  autosaved. Closing still prompts only if something is unsaved.

## Phase 3 — Viewing

### ⋯ menu

A **⋯** button at the right of the toolbar opens a menu (keyboard
accessible; Esc closes):
`Theme ▸ System / Light / Dark` · `Autosave` (checkbox) · `Zoom in` ·
`Zoom out` · `Reset zoom` · `Export HTML…` · `Print…` · `Check for updates…`
(Phase 4) · `About Folio` (version).

### Zoom

- **Ctrl+=** (and Ctrl++), **Ctrl+-**, **Ctrl+0** change the document and
  editor text size in 10% steps, 70%–200%, default 100%. Remembered
  across launches. The app chrome does not scale. Ctrl+mouse wheel does
  the same over the document.

### Theme

- `System` follows Windows (today's behaviour); `Light` and `Dark` force
  the theme, including editor, code highlighting, diagrams and the window
  title bar where Tauri allows. Remembered. The web viewer keeps following
  the system only.

### Diagrams (Mermaid)

- A fenced block with language `mermaid` renders as a diagram in Read and
  the Split preview; its source is unchanged in Edit.
- Mermaid runs with `securityLevel: 'strict'` and `htmlLabels: false`;
  its SVG is sanitised again before insertion. Diagrams follow the theme.
- Invalid diagram → the code block is shown as code with a small
  `Diagram error: <message>` line under it.
- Mermaid is bundled (offline) and loaded only when a document contains a
  mermaid block.

### Maths (KaTeX)

- `$…$` inline and `$$…$$` display maths render in Read and the Split
  preview. Rules: the opening `$` is not followed by a space, the closing
  `$` is not preceded by a space and not followed by a digit, `\$` is a
  literal dollar, and nothing inside code spans/blocks is maths. `$$` may
  span lines.
- Implemented as an opt-in renderer option, `createRenderer(win, { math:
  true })`; the web viewer calls `createRenderer(win)` and is unchanged.
  The renderer emits placeholders carrying the TeX source (escaped); the
  desktop renders them with KaTeX (`trust: false`, `throwOnError: false`,
  errors shown in red). KaTeX CSS and fonts are bundled.

### Export and print

- **Export HTML…** asks for a path (default `<name>.html`, filter
  `*.html`) and writes one self-contained file: the rendered document with
  diagrams and maths, the document styles inlined, local images embedded
  as data URLs (images over 10 MB are left as links), the current theme,
  and the document title. No scripts.
- **Print…** opens the system print dialog showing only the document
  (no tab bar, sidebar, toolbar or banners; light colours; code blocks
  wrap). Saving as PDF is choosing *Microsoft Print to PDF*.

## Phase 4 — App comfort

### Session restore

- On quit, `settings.session` stores the open tabs that have a path (with
  their mode), the active tab and the open folder; sidebar state and tab
  are stored with the other settings.
- On launch: restore drafts (Phase 2), then the session's tabs (skipping
  missing files silently), the folder and the sidebar, then open files
  from the command line / a second launch on top (they become active).
- Session restore never prompts.

### Sidebar file operations

- Right-click a row in Files (or press the row's ⋯ / Shift+F10) for:
  **New file**, **New folder**, **Rename**, **Delete**, **Show in Explorer**.
  The folder header has New file / New folder too.
- New file / folder / Rename edit the name inline in the tree (Enter
  confirms, Esc cancels). New files get `.md` added if the name has no
  extension. Invalid names (`\ / : * ? " < > |`, empty) show the error
  inline. A new file opens in a tab in Edit mode.
- Rename of an open file updates its tab (path, title, recent); renaming a
  folder updates tabs inside it. A dirty tab keeps its text.
- **Delete** asks `Move <name> to the Recycle Bin?` (**Delete** /
  **Cancel**); for a folder: `Move <name> and everything in it to the
  Recycle Bin?`. An open tab of a deleted file follows the existing
  `was deleted or moved.` flow.
- Errors show `Couldn't <action> <name>: <reason>` in the app banner.

### Auto-update

- 10 s after launch (once per launch) Folio checks
  `https://github.com/suhaib-md/Folio/releases/latest/download/latest.json`.
  If a newer version exists, an app banner shows
  `Folio <version> is available.` **Install and restart** / **Later**.
  Network errors are silent.
- **Check for updates…** in the ⋯ menu does the same and also reports
  `Folio is up to date.` or the error.
- **Install and restart** first runs the normal window-close flow (unsaved
  prompts; Cancel aborts the update), then downloads, verifies the
  signature, installs and relaunches.
- Packaging: `bundle.createUpdaterArtifacts: true`; the updater public key
  lives in `tauri.conf.json`; the CI release job signs with the GitHub
  secrets `TAURI_SIGNING_PRIVATE_KEY` and
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` and uploads `latest.json` to the
  release. Releases are still drafts until the user publishes them; the
  updater only sees published releases.
- One-time user step (at the start of Phase 4): run
  `npx @tauri-apps/cli signer generate -w folio-updater.key` on their PC,
  add the private key and password as the two repo secrets, and send the
  **public** key to be committed. The private key never goes through chat
  or the repo. Until the public key exists, the updater is built but the
  check is disabled (menu item shows `Updates not configured`).

## Security

- CSP unchanged except what bundled KaTeX fonts/Mermaid need (`font-src
  'self'` is covered by `default-src 'self'`); no remote loads.
- Maths and diagrams never execute content: KaTeX `trust: false`;
  Mermaid `securityLevel: 'strict'` plus a second DOMPurify pass with the
  SVG profile.
- `write_image` and the file operations only act on paths the user chose
  (inside the open folder for sidebar actions; next to the document for
  images); `write_image` refuses non-image extensions and overwrites.
- Exported HTML contains no scripts.
- Updater: signature-verified packages only (Tauri updater requirement).
- New capabilities: `updater:default`, `process:allow-restart`, and the
  opener's reveal permission.

## Testing

- **Rust:** search (skips, case, cap, cancellation, line/offset), file ops
  (create/rename/exists errors, case-only rename), `write_image`
  (extension check, no overwrite, parent creation), drafts round trip,
  settings defaults on missing/corrupt. Run on Linux and Windows CI.
- **JS (node):** outline extraction (levels, setext, code fences ignored,
  current-section), fuzzy ranking, find match iteration (case, wrap),
  formatting toggles, word count, draft scheduling, session merge order,
  settings defaults, maths tokenizer rules and the web renderer unchanged
  without the option, export builder (no scripts, images embedded).
- **Browser (fake backend):** every feature above, light/dark, 480px.
- **Release:** after Phase 4, tag `v0.3.0`, publish the draft, and confirm
  a 0.3.0 install sees a test `v0.3.1` update (manual, with the user).

## Out of scope

Multiple windows, multiple folders, git integration, spell-check
dictionaries, custom themes/CSS, plugins, code signing, macOS/Linux builds,
cloud sync, collaborative editing, exporting to Word/DOCX.
